Dato, información y sistema de informaciónData, information, and information systems

Un dato es un hecho registrado: una cifra, un evento, una transacción. La información, en cambio, es ese dato ya procesado y comunicado de forma que puede entenderse. "22 ºC" es un dato suelto; "22 ºC en Sevilla el 15 de julio" ya es información, porque tiene contexto. Cuando esa información se asimila y se usa para decidir, se convierte en conocimiento. A datum is a recorded fact: a figure, an event, a transaction. Information is that same data once it has been processed and communicated in a way people can understand. "22 °C" is a bare data point; "22 °C in Seville on July 15th" is already information, because it has context. Once that information is absorbed and used to make a decision, it becomes knowledge.

Toda empresa opera sobre un sistema de información: un conjunto organizado de elementos —informatizados o no— destinados a tratar y administrar datos para cubrir una necesidad concreta: saber si hay que reponer un producto, lanzar una oferta o contratar a alguien porque se están perdiendo ventas. Every company runs on an information system: an organised set of elements — computerised or not — used to process and manage data to meet a specific need, such as knowing whether to restock a product, launch an offer, or hire someone because sales are being lost.

"El hombre siempre ha tenido la necesidad de almacenar información" — las tablillas de arcilla con documentación económica de la antigua Mesopotamia lo demuestran. "Humans have always had the need to store information" — the clay tablets recording economic transactions in ancient Mesopotamia are the proof.

La evolución del almacenamientoThe evolution of storage

De la cinta secuencial a la base de datos distribuida en la nube. From sequential tape to the distributed cloud database.

≈3000 a. C.BCE

Tablillas de arcillaClay tablets

Documentación económica cuneiforme en Mesopotamia: el primer registro conocido de la necesidad humana de guardar datos de forma duradera y consultable. Cuneiform economic records from Mesopotamia — the earliest known evidence of the human need to keep data in a durable, retrievable form.

1950

Cintas magnéticasMagnetic tape

Sólo permitían lectura secuencial y ordenada: para llegar a un registro había que recorrer todos los anteriores. Provocaban mucha redundancia de datos. They could only be read sequentially, in order: reaching one record meant passing through every one before it. This caused heavy data redundancy.

1960

Discos magnéticos y modelos jerárquico / en redMagnetic disks and the hierarchical / network models

El acceso directo generaliza el disco magnético y aparecen las bases de datos jerárquicas (información en árbol, de arriba a abajo — el registro de Windows es un ejemplo actual) y en red (relaciones muchos-a-muchos entre nodos). Direct access made the magnetic disk the norm, giving rise to hierarchical databases (tree-shaped, top-down information — the Windows registry is a present-day example) and network databases (many-to-many relationships between nodes).

1970

El modelo relacional (Edgar F. Codd, IBM)The relational model (Edgar F. Codd, IBM)

Codd publica "A Relational Model of Data for Large Shared Data Banks", basado en lógica de predicados y teoría de conjuntos. Nace el modelo más extendido hasta hoy: tablas bidimensionales relacionadas entre sí. Codd publishes "A Relational Model of Data for Large Shared Data Banks," grounded in predicate logic and set theory. This launches the most widely used model even today: two-dimensional tables linked to one another.

1980

DB2 y el nacimiento de SQLDB2 and the birth of SQL

IBM lanza el motor DB2 para su sistema operativo MVS y poco después crea SQL (Structured Query Language), el lenguaje de consultas que sigue dominando las bases de datos relacionales. IBM releases the DB2 engine for its MVS operating system and shortly after creates SQL (Structured Query Language), the query language that still dominates relational databases.

1990

Bases de datos distribuidas y orientadas a objetosDistributed and object-oriented databases

IBM reparte una base de datos enorme entre varios servidores conectados a gran velocidad (piénsese en la base de datos de Facebook). En paralelo, IBM y Oracle añaden capacidad de manipular objetos, imágenes, gráficos y voz. IBM splits huge databases across several high-speed connected servers — think of Facebook's database today. At the same time, IBM and Oracle add the ability to manipulate objects, images, graphics and voice.

2000 → hoynow

Multidimensional, NoSQL y Big DataMultidimensional, NoSQL and Big Data

Los modelos multidimensionales impulsan el Data Warehouse y el OLAP; el estallido del Big Data trae las soluciones NoSQL — clave-valor, documental, grafos y columnares — pensadas para rendimiento y escalabilidad por encima de la rigidez de las tablas. The multidimensional models power Data Warehousing and OLAP; the Big Data explosion brings NoSQL solutions — key-value, document, graph and column-based — built for performance and scalability over rigid tables.

Ficheros: la solución anterior a la base de datosFiles: the solution before databases

Antes de que existieran las aplicaciones de bases de datos, las empresas gestionaban su información con cajones, carpetas y fichas de cartón — y, ya en el terreno informático, con ficheros de texto plano diseñados a medida para cada aplicación, sin ningún formato común entre ellos. Before database applications existed, companies managed their information with drawers, folders and index cards — and, once computers arrived, with plain text files custom-built for each application, with no shared format between them.

Un fichero es, formalmente, una secuencia de bits que organiza información relacionada con un mismo aspecto. Cuando almacena datos, se dice que está formado por registros (la información de un mismo elemento, por ejemplo un estudiante) y cada registro se divide en campos (su nombre, su email…). Formally, a file is a sequence of bits that organises information related to one subject. When it stores data, it is said to be made up of records (the information for a single element — a student, say) and each record is split into fields (their name, their email…).

TEXTO PLANO / ASCIIPLAIN TEXT / ASCII

Legibles por cualquier editorReadable in any editor

Secuencias de caracteres en una codificación conocida (ASCII, Unicode). Se abren con el Bloc de notas o Vi. Ejemplos: .txt, .csv, ficheros de configuración (.ini, .conf), código fuente (.sql, .java) y páginas web (.html, .xml). Sequences of characters in a known encoding (ASCII, Unicode). They open in Notepad or Vi. Examples: .txt, .csv, configuration files (.ini, .conf), source code (.sql, .java) and web pages (.html, .xml).

BINARIOSBINARY

Ilegibles sin la aplicación adecuadaUnreadable without the right application

Codifican información para una aplicación concreta; abiertos en un editor de texto muestran símbolos sin sentido. Ejemplos: .exe, .pdf, .docx, .jpg, .mp4. Los propios ficheros de un SGBD (como los .frm/.ibd de MariaDB) son binarios. They encode information for one specific application; opened in a text editor they show meaningless symbols. Examples: .exe, .pdf, .docx, .jpg, .mp4. A DBMS's own files (like MariaDB's .frm/.ibd) are binary.

ACCESO SECUENCIALSEQUENTIAL ACCESS

Un registro tras otroOne record after another

Típico de las cintas magnéticas: para llegar a un registro hay que recorrer todos los anteriores. Dentro de este grupo distinguimos los ficheros encadenados (cada registro apunta al siguiente) y los indexados (una zona de datos y una zona de índice con clave + dirección, como el índice de un libro). Typical of magnetic tape: reaching a record means passing through every one before it. Within this group we distinguish chained files (each record points to the next) and indexed files (a data zone plus an index zone with key + address, like a book's index).

ACCESO DIRECTO / ALEATORIODIRECT / RANDOM ACCESS

Saltar directo al registroJumping straight to the record

Permite ir directamente al registro que interesa sin recorrer los anteriores — lo que hoy hacen de forma natural los discos SSD y NVMe, minimizando además la fragmentación de los datos. Lets you go straight to the record you need without passing through the earlier ones — which is exactly what today's SSD and NVMe drives do naturally, while also minimising data fragmentation.

Qué es una base de datosWhat a database is

Una base de datos es un conjunto de datos interrelacionados, organizados en ficheros binarios, con integridad y redundancia mínima, accesibles por varios usuarios y aplicaciones a la vez. A database is a set of interrelated data, organised in binary files, with integrity and minimal redundancy, accessible to several users and applications at the same time.

Dos ideas quedan escondidas en esa definición: la integridad (los datos son correctos y completos) y la redundancia mínima (cada dato existe en un único lugar). Toda base de datos, además, debe permitir insertar, modificar y borrar información, y se compone tanto de datos como de metadatos — la descripción de su propia estructura, guardada en el diccionario de datos. Two ideas hide inside that definition: integrity (the data is correct and complete) and minimal redundancy (each piece of data exists in a single place). Every database must also support inserting, updating and deleting information, and it is made up of both data and metadata — the description of its own structure, stored in the data dictionary.

El sistema gestor de bases de datos (SGBD)The database management system (DBMS)

Es importante no confundir los dos conceptos: la base de datos es la información organizada; el SGBD (o DBMS, DataBase Management System) es el software que la crea, manipula y administra, sirviendo de interfaz entre el usuario y los datos. Oracle, MySQL, MariaDB, Access, MongoDB o PostgreSQL son SGBD — no bases de datos en sí mismas. It's important not to confuse the two concepts: the database is the organised information; the DBMS is the software that creates, manipulates and administers it, acting as the interface between the user and the data. Oracle, MySQL, MariaDB, Access, MongoDB and PostgreSQL are DBMSs — not databases themselves.

Arquitectura en 3 niveles (ANSI/SPARC)Three-level architecture (ANSI/SPARC)

A mediados de los 70, el grupo ANSI/SPARC separó los datos de las aplicaciones en tres esquemas, permitiendo independencia lógica y física. In the mid-1970s, the ANSI/SPARC group split data from applications into three schemas, enabling both logical and physical independence.

NIVEL EXTERNO — el más cercano al usuarioEXTERNAL LEVEL — closest to the user La salida de datos: un formulario, un listado, un informe, la respuesta a una consulta concreta.The data output: a form, a listing, a report, the answer to one specific query.
NIVEL CONCEPTUAL — el diseñoCONCEPTUAL LEVEL — the design La unión de todos los datos y sus relaciones, representados de forma lógica — en una BD relacional, en formato de tabla.The union of all data and its relationships, represented logically — in a relational database, as tables.

Legislación sobre protección de datosData protection legislation

Las bases de datos que guardan información de personas están reguladas en Europa por el RGPD (Reglamento General de Protección de Datos, 2016/679) y, en España, por la LOPDGDD (Ley Orgánica 3/2018), que lo adapta a la realidad española. La AEPD (Agencia Española de Protección de Datos) es quien vela por su cumplimiento. Databases that hold personal information are regulated across Europe by the GDPR (General Data Protection Regulation, 2016/679) and, in Spain, by the LOPDGDD (Organic Law 3/2018), which adapts it to Spanish law. The AEPD (Spanish Data Protection Agency) is the body that enforces it.

En resumenIn summary

  1. Un ficheroA file es una estructura que crea el sistema operativo para guardar información; su tipo y formato determinan cómo se interpreta. is a structure created by the operating system to hold information; its type and format determine how it is interpreted.
  2. Una base de datosA database se organiza en tablas con registros y campos relacionados entre sí, y almacena también consultas, índices y vistas. is organised into tables with related records and fields, and also stores queries, indexes and views.
  3. Los modelos de datosData models han evolucionado del jerárquico y en red al relacional — el más usado — y, más recientemente, a las soluciones NoSQL y distribuidas. have evolved from hierarchical and network models to the relational model — still the most widely used — and more recently to NoSQL and distributed solutions.
  4. Un SGBDA DBMS es el software que crea y administra bases de datos: garantiza integridad, seguridad, concurrencia y recuperación ante fallos. is the software that creates and administers databases: it guarantees integrity, security, concurrency and failure recovery.
  5. SQL es la interfaz entre el usuario y la base de datos, dividida en cuatro sublenguajes: DML, DDL, DCL y TCL. is the interface between the user and the database, split into four sub-languages: DML, DDL, DCL and TCL.
  6. El RGPD y la LOPDGDDThe GDPR and the LOPDGDD obligan a tratar los datos personales con consentimiento, transparencia y seguridad, bajo la supervisión de la AEPD. require personal data to be handled with consent, transparency and security, under the AEPD's supervision.
